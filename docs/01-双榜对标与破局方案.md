### 痛点归纳（跨 10 款应用收敛出的 5 条结构性矛盾）

1. **付费墙形态恶劣**：不是"订阅解锁全部"，而是"逐章买币 + 每日票"，用户无法预估成本。
2. **广告侵入阅读流**：不是开屏广告，而是翻页中途跳浏览器。
3. **数据去向不透明**：Cookie 中间商、第三方共享、传输未加密——而这是阅读类应用最不该有的问题。
4. **没有账号 = 没有迁移能力**：换机即从零开始。
5. **地区锁**：IP 决定你能读什么，跨区用户被迫用灰色方案。

### 底座选定结论

> **唯一主底座：`mihonapp/mihon`**
> **辅助借鉴：`komikku-app/komikku`（UI/主题与建议算法）、`jobobby04/TachiyomiSY`（阅读器交互与 Library 组织）**

**理由（按权重）**

1. **活跃度断层第一**：25,592 Star、1,844 Fork、776 open issue、主干每日提交。分叉一个活跃上游，才能持续 rebase 拿到安全修复；分叉 Kotatsu（停更一年）等于接手一个死项目。
2. **技术栈匹配度最高**：AGP 9.5.2 + Kotlin 2.4.21 + Compose BOM 2026.11.01 + Metro DI + SQLDelight，已是 2026 年原生安卓一线水准，**不需要重写即可直接承载新功能**。
3. **协议可吸收**：Apache-2.0 是单向兼容 GPL-3.0 的——我们可以在保留上游 Apache-2.0 版权声明（NOTICE）的前提下，把**新增代码与整体发行**置于 GPL-3.0。这正好满足 SOP 的"默认 GPL-3.0"要求，且法律上干净。
4. **i18n 基建已就位**：`i18n` 模块已有 **70 个 locale 目录**（含 RTL 的 ar/he/fa/ur），并通过 `GenerateLocalesConfigTask` 自动生成 `locales_config.xml`。SOP 要的"50 语种 + 系统自动跟随 + 英语兜底"在这个底座上是**验收项而非开发项**——这能砍掉整条最容易翻车的工作流。
5. **换皮成本可控**：`namespace` 与 `applicationId` 解耦（`namespace = eu.kanade.tachiyomi`，`applicationId = app.mihon`），只改 `applicationId` 即可与上游共存安装、独立存储、独立 FileProvider authority——分叉维护成本大幅下降。

**明确不选**：Kotatsu（协议最合但停更）、Suwayomi（服务端架构，移动端要重写 UI 层）、copymanga（单一区域源）、Neko（单源天花板）。

## 三、6 个差异化创新点（可落地 / 可编码 / 可验证）

每个创新点都对应上文一条真实差评痛点，给出落点模块与验收方式。

### D1 · Privacy Ledger 隐私审计面板
- **狙击痛点**：MANGA Plus 被投诉"强制写入 640 家数据中介 Cookie"；K MANGA 的 Data Safety 自认"与第三方共享、传输未加密"。用户不是不想信，是**没有可验证的证据**。
- **技术落地**：在 OkHttp 客户端挂 `EventListener` + `Interceptor`，把每次请求的 host / 时间 / 触发模块写入本地 SQLDelight 表（仅本地、可一键清空）；新增 Compose 页面按域名聚合展示，支持导出 `.txt` 审计报告。判据：应用发出的**每一个**网络域名都能在面板里被看到。
- **差异化优势**：商业应用只能"承诺"不追踪，我们让他们**自己查**。这是唯一能对抗"你在偷我数据"这类差评的功能。

### D2 · 离线优先下载中枢 v2
- **狙击痛点**：MANGA Plus 明确"无离线阅读"；订阅制应用一旦退订，已下载内容即刻失效。读者真正的资产是"我下载好的那一份"。
- **技术落地**：在既有 `DownloadCache` 之上加 `StorageBudgetManager`——设定存储上限（如 8GB），按"未读优先 / 已读超 30 天优先淘汰"自动腾挪；队列支持仅 Wi-Fi、仅充电、批量重试；下载完成落盘为开放格式目录，卸载重装可指回原目录复用。
- **差异化优势**：把"下载"从缓存变成**资产**。竞品的下载是租的，我们的是你的。

### D3 · 零账号跨设备迁移
- **狙击痛点**：MANGA Plus 差评原文——"没有账号体系，换设备就得重新订阅/重新开始"。
- **技术落地**：不做云、不做账号。① 加密备份包（`.sumika`，AES-GCM + 用户口令）；② 局域网直传：手机 A 起临时 HTTP 服务，手机 B 扫码拉取，全程不出子网。
- **差异化优势**：既解决迁移，又不引入任何服务器与隐私面。开源社区最认这个解法。

### D4 · 本地阅读洞察（无云端统计）
- **狙击痛点**：所有竞品都不给你"我今年读了多少"，因为数据要拿去变现。
- **技术落地**：SQLDelight 新增 `reading_session` 表（章节、起止时间、页数），Compose 画周/月热力与连续天数；数据永不出设备，面板内明示"仅本地"。
- **差异化优势**：把"隐私"从口号变成**用户能炫耀的东西**——可导出分享图。

### D5 · Today 一屏续读
- **狙击痛点**：Mihon 系产品的 Library 是"书架"，不是"今天读什么"；商业应用的发现页又被算法和推广位塞满（MANGA Plus 差评："按分类/热度排序根本不工作，还封顶 100 条"）。
- **技术落地**：新增 Today 入口，聚合三件事：① 追更中有新章的系列（按更新时间）；② 上次读到一半未读完的章；③ 已下载未读。纯本地查询，零推荐算法。
- **差异化优势**：打开即读，消灭"在书架里翻五分钟找书"的摩擦。

### D6 · 50 语种真覆盖 + RTL 全镜像 + 应用内独立语言
- **狙击痛点**：地区锁 + 界面只有英语/日语，非英语用户被迫在灰色汉化组之间跳。
- **技术落地**：核对 SOP 50 语种清单与现有 70 个 locale 目录的差集并补齐；`android:supportsRtl="true"`，阿拉伯语/希伯来语/波斯语/乌尔都语做镜像走查；`locales_config.xml` 由构建任务自动生成，Android 13+ 支持系统设置里单独改本应用语言；未覆盖语种回落 `values/` 英语。
- **差异化优势**：这是唯一一条**竞品结构性做不到**的——他们每加一个语种都要过当地法务与版权方，我们只要一个 PR。

### 附·SOP 强制行为（非差异化，但必须实现）
- **B1 温和口碑**：严禁首启弹窗；计数器在"完整读完第 3 个章节"后触发一次礼貌提示，拒绝后 90 天不再打扰。
- **B2 品牌换皮**：`applicationId=app.sumika`、应用名 Sumika、自适应图标、暗黑优先配色；保留上游版权声明与 GPL-3.0 全文。

## 五、风险与合规提示（必须在上架前决策）

1. **Google Play 的政策风险（最高优先级）**：Play 对"可加载第三方未授权内容源"的阅读器有明确拒绝先例（历史上 Tachiyomi 系从未上架 Play）。策略调整：**首发走 GitHub Releases + IzzyOnDroid + F-Droid**，把 Play 作为"可选且延后"的渠道；Play 版本若要过审，需默认不预置任何第三方源、仅保留本地文件阅读（`source-local`）与用户自建源。
2. **协议合规**：上游 Apache-2.0 要求保留版权与 NOTICE，Apache-2.0 与 GPL-3.0 单向兼容，不得反过来把上游声明改成 GPL。仓库根目录同时放 `LICENSE`（GPL-3.0）与 `NOTICE`（上游声明）。
3. **"零商业化"的可信度**：一旦在应用内加任何捐赠入口，必须在代码里可审计；不得引入任何统计 SDK。Mihon 上游自带 `telemetry` 模块（Firebase Crashlytics / Analytics 变体），本项目**必须全程 `-Pinclude-telemetry=false`**，并在 CI 与本地构建中固化为默认值，否则"无追踪"承诺当场破产。
4. **数据安全声明一致性**：Play 的 Data Safety 表必须与 Privacy Ledger 的实际观测结果一致——这也是我们把 D1 做成可导出审计报告的原因。
